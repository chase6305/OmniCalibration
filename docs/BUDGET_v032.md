# 续算预算与异常回退（v0.3.2）

本次验证保留 v0.3.0、v0.3.1 的原始评估和复现包，不用新结果覆写历史未接受案例。
所有结果来自合成数据，尚未验证实机精度。

## 参数与预算

| 参数 | 默认值 | 含义 |
|---|---|---|
| `outer_iterations` | 由调用方指定 | 单个 ICP 阶段的外迭代上限 |
| `local_continuation` | `True` | 为符合条件、尚未稳定的候选追加一次续算 |
| `continuation_iterations` | `None` | 单次续算上限；`None` 沿用 `outer_iterations` |

显式续算上限必须是 1 到 `outer_iterations` 的整数。原阶段和相机重试仍各有自身预算，
因此它不是整个搜索的总预算，也不是墙钟超时；内层函数评估上限和点数同样影响耗时。
设置 `local_continuation=False` 可禁用续算。

这些选项通过 Python API 的 `solver_options` 传入。例如：

```python
# 对已有配置和观测调用；其余条件应与前次拟合保持一致。
from omnicalib.assets import calibrate_dataset

result = calibrate_dataset(
    "configs/marvin_dual.json",
    "observations.npz",
    outer_iterations=35,
    solver_options={"continuation_iterations": 10},
)
```

预算不足以满足原始连续稳定条件时，候选保持未稳定，不能因为预算用完就声明收敛。
更多续算前提和手动继续接口见 [数据指南](DATA_FORMAT.md#在原候选解上继续求解)。

## 异常回退

局部续算出现 `ValueError` 时记录错误并保留原候选；若允许相机重试，继续原有搜索流程。
异常不会转为成功，也不会吞掉任意程序错误。抛错的子求解没有返回部分历史，
因此错误状态单独记录，不能把它当作一条完整迭代轨迹。

回归测试覆盖实际执行上限、预算不足时不得伪报收敛、异常时保留原候选，以及完整步长停止与累计历史。
审计器递归检查嵌套日志的预算和异常状态，并用超预算日志验证拒绝行为。

## 64 次合成验证

八个新种子 × 八类场景，64/64 次运行完成，审计通过，18 个引用资产文件未变。
56 个有锚定案例通过内部提案门槛，8 个无锚定案例全部保留为不可观测。

| 场景 | 接受/返回 | 最坏关节误差 (°) |
|---|---:|---:|
| 左臂 | 8/8 | 0.019297 |
| 右臂 | 8/8 | 0.019711 |
| 双臂 | 8/8 | 0.034459 |
| 双臂、共享编码器噪声 | 8/8 | 0.031471 |
| 双臂、尺度与离群点 | 8/8 | 0.031341 |
| 同上、续算上限 10 | 8/8 | 0.031341 |
| 双臂、距离平方轴向噪声 | 8/8 | **0.201023** |
| 左臂、无固定参考 | 0/8 | —（参数不唯一） |

**距离平方噪声场景虽通过内部质量门槛，最坏误差仍超过 0.1° 参考线。**
内部接受不保证实际精度；该结果完整保留。

尺度离群点默认与上限 10 的八组成对结果相同，但都没有触发续算，
因此不能据此宣称预算选项改善耗时或精度。实际预算上限由定向单元测试验证；
平方噪声日志中保留了一次 35 步续算。嵌套诊断可能保存同一次尝试的副本，
日志数量不能直接解释为实际尝试次数。
